### Ключевые принципы

1. **Карточки НЕ хранятся в БД** - генерируются динамически при каждом запросе
2. **motivation_cards - это ЛОГ**, а НЕ источник карточек
3. **Временное окно: 48 часов** - берутся только последние записи
4. **Максимум 3 карточки** - из непросмотренных записей + шаблонные
5. **Уникальные градиенты** - назначаются на основе индекса в массиве

## 🔄 Как работает генерация карточек

### Алгоритм (motivations Edge Function)

```typescript
// Шаг 1: Получить язык пользователя
const userLanguage = profiles[0]?.language || 'ru';

// Шаг 2: Получить последние 10 записей за 48 часов
const yesterday = new Date(Date.now() - 48 * 60 * 60 * 1000);
const entries = await fetch(
  `${supabaseUrl}/rest/v1/entries?user_id=eq.${userId}&created_at=gte.${yesterday.toISOString()}&order=created_at.desc&limit=10`
);

// Шаг 3: Получить просмотренные entry_id из motivation_cards
const viewedCards = await fetch(
  `${supabaseUrl}/rest/v1/motivation_cards?user_id=eq.${userId}&is_read=eq.true&created_at=gte.${yesterday.toISOString()}`
);
const viewedIds = viewedCards.map(c => c.entry_id);

// Шаг 4: Фильтровать непросмотренные записи
const unviewedEntries = entries.filter(e => !viewedIds.includes(e.id));

// Шаг 5: Создать карточки из непросмотренных записей (max 3)
const cards = unviewedEntries.slice(0, 3).map(entry => ({
  id: entry.id,
  title: entry.ai_summary?.split(' ').slice(0, 8).join(' ') + '...',
  description: entry.ai_insight || entry.ai_summary || entry.text,
  sentiment: entry.sentiment || 'positive',
  gradient: '', // Будет назначен позже
}));

// Шаг 6: Добавить шаблонные карточки если < 3
if (cards.length < 3) {
  const defaultCards = getDefaultMotivations(userLanguage);
  const needed = 3 - cards.length;
  cards.push(...defaultCards.slice(0, needed));
}

// Шаг 7: Назначить уникальные градиенты
cards.forEach((card, index) => {
  card.gradient = getGradientByIndex(index, card.sentiment);
});

return { cards };
```

## 📊 Источники данных

### Таблица `entries`

**Назначение**: Основной источник данных для карточек

**Поля используемые для карточек**:
- `id` - уникальный идентификатор записи
- `user_id` - владелец записи
- `created_at` - дата создания (для фильтрации 48 часов)
- `ai_summary` - краткое резюме от AI (используется для title)

- `text` - оригинальный текст записи (fallback для description)
- `sentiment` - настроение (positive/neutral/negative) для выбора градиента

**Временное окно**: Последние 48 часов

**Лимит**: 10 записей (для производительности)

## 🔍 Логика фильтрации просмотренных

### Как определяется "просмотренная" карточка

1. **Пользователь свайпает карточку** → вызывается `POST /motivations/mark-read`
2. **Создается запись в motivation_cards**:
   ```sql
   INSERT INTO motivation_cards (user_id, entry_id, is_read)
   VALUES ('user-uuid', 'entry-uuid', true);
   ```
3. **При следующем запросе карточек**:
   - Получаем все `entry_id` из `motivation_cards` где `is_read = true`
   - Фильтруем записи: `entries.filter(e => !viewedIds.includes(e.id))`
   - Результат: только непросмотренные записи становятся карточками

### Пример

**Сценарий**:
- У пользователя 5 записей за последние 48 часов: E1, E2, E3, E4, E5
- Пользователь просмотрел карточки из E1 и E2

**Таблица motivation_cards**:
```
| user_id | entry_id | is_read | created_at          |
|---------|----------|---------|---------------------|
| U1      | E1       | true    | 2025-11-15 10:00:00 |
| U1      | E2       | true    | 2025-11-15 10:05:00 |
```

**Результат генерации карточек**:
1. Получаем записи: [E1, E2, E3, E4, E5]
2. Получаем просмотренные: [E1, E2]
3. Фильтруем: [E3, E4, E5]
4. Берем первые 3: [E3, E4, E5]
5. Возвращаем 3 карточки из E3, E4, E5

## 👆 Свайп и отметка "просмотрено"

### Frontend (MotivationCardsSection.tsx)

```typescript
const handleSwipe = async (cardId: string, direction: 'left' | 'right') => {
  // Оптимистичное обновление UI
  setCards(prev => prev.filter(c => c.id !== cardId));

  // Отправляем запрос на сервер
  await fetch(`${supabaseUrl}/functions/v1/motivations/mark-read`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': `Bearer ${token}`,
    },
    body: JSON.stringify({
      entry_id: cardId,
      direction: direction, // 'left' или 'right'
    }),
  });
};
```

### Backend (motivations Edge Function)

```typescript
// POST /motivations/mark-read
async function markCardAsRead(userId: string, entryId: string) {
  // Создаем запись в motivation_cards
  await supabase
    .from('motivation_cards')
    .insert({
      user_id: userId,
      entry_id: entryId,
      is_read: true, // ВСЕГДА true
      created_at: new Date().toISOString(),
    });

  return { success: true };
}
```

### Важные детали

- **Оптимистичное обновление**: карточка исчезает сразу, не ждем ответа сервера
- **Направление свайпа**: сохраняется для аналитики (left/right)
- **Идемпотентность**: повторный вызов с тем же entry_id не создаст дубликат (unique constraint)

## 🔄 Обновление карточек

### Когда обновляются карточки

1. **При каждом открытии главного экрана**
   - Frontend вызывает `GET /home-screen-data`
   - home-screen-data вызывает `GET /motivations/cards/{userId}`
   - motivations генерирует карточки заново

2. **При pull-to-refresh**
   - Пользователь тянет экран вниз
   - Вызывается тот же API
   - Карточки обновляются

3. **При создании новой записи**
   - Пользователь создает запись
   - Запись попадает в БД
   - При следующем открытии главного экрана → новая карточка появится

### Частота обновления

- **Автоматически**: каждые 60 секунд (если экран открыт)
- **Вручную**: pull-to-refresh
- **При навигации**: при возврате на главный экран

### Кеширование

**localStorage cache** (1 час TTL):
```typescript
const CACHE_KEY = 'home_screen_data';
const CACHE_TTL = 60 * 60 * 1000; // 1 час

// Проверяем кеш
const cached = localStorage.getItem(CACHE_KEY);
if (cached) {
  const { data, timestamp } = JSON.parse(cached);
  if (Date.now() - timestamp < CACHE_TTL) {
    return data; // Возвращаем из кеша
  }
}

// Запрашиваем с сервера
const response = await fetch('/home-screen-data');
const data = await response.json();

// Сохраняем в кеш
localStorage.setItem(CACHE_KEY, JSON.stringify({
  data,
  timestamp: Date.now(),
}));
```

## 🎨 Шаблонные карточки

### Когда добавляются

Если после фильтрации непросмотренных записей получилось **< 3 карточек**, добавляются шаблонные мотивационные сообщения.

### Источник шаблонов

**Функция `getDefaultMotivations(language)`** в motivations Edge Function:

```typescript
function getDefaultMotivations(language: string) {
  const templates = {
    ru: [
      {
        id: 'default-1',
        title: '🌟 Начните день с записи',
        description: 'Запишите свои мысли и цели на сегодня',
        sentiment: 'positive',
      },
      {
        id: 'default-2',
        title: '💪 Отметьте достижение',
        description: 'Даже маленькая победа заслуживает признания',
        sentiment: 'positive',
      },
      {
        id: 'default-3',
        title: '🎯 Поставьте цель',
        description: 'Определите что хотите достичь на этой неделе',
        sentiment: 'neutral',
      },
    ],
    en: [
      {
        id: 'default-1',
        title: '🌟 Start your day with a note',
        description: 'Write down your thoughts and goals for today',
        sentiment: 'positive',
      },
      // ... и т.д.

### Многоязычность

Шаблоны доступны на **7 языках**: ru, en, es, de, fr, zh, ja

### Приоритет

1. **Сначала**: карточки из непросмотренных записей (max 3)
2. **Потом**: шаблонные карточки (чтобы всегда было 3 карточки)

**Пример**:
- Непросмотренных записей: 1
- Добавляем: 2 шаблонные карточки
- Итого: 3 карточки (1 из записи + 2 шаблонные)

## 🔔 Push-уведомления

### Связь карточек с уведомлениями

**ВАЖНО**: Карточки НЕ отправляют push-уведомления напрямую. Уведомления отправляются при создании записей.

### Архитектура уведомлений

```

│  ┌──────────────────────────────────────────────────────┐   │
│  │  entries INSERT                                      │   │
│  │  - Пользователь создает запись                       │   │
│  │  - Срабатывает Database Webhook                      │   │
│  └──────────────────────────────────────────────────────┘   │

│              Edge Function                                   │
│  ┌──────────────────────────────────────────────────────┐   │
│  │  push-realtime-trigger                               │   │
│  │  - Получает событие INSERT                           │   │

## 📖 Сценарии работы

### Сценарий 1: Новый пользователь (первый день)

**Шаг 1**: Пользователь регистрируется
- Создается профиль в таблице `profiles`
- Записей нет, motivation_cards пустая

**Шаг 2**: Пользователь открывает главный экран
- Frontend вызывает `GET /home-screen-data`
- home-screen-data вызывает `GET /motivations/cards/{userId}`
- motivations находит 0 записей за 48 часов
- Добавляет 3 шаблонные карточки
- Возвращает: 3 шаблонные карточки

**Результат**: Пользователь видит 3 мотивационных сообщения:
1. 🌟 Начните день с записи
2. 💪 Отметьте достижение
3. 🎯 Поставьте цель

**Шаг 3**: Пользователь свайпает первую карточку
- Frontend вызывает `POST /motivations/mark-read` с `entry_id: 'default-1'`
- Backend НЕ создает запись (это шаблонная карточка, не из entries)
- Карточка исчезает из UI

**Шаг 4**: Пользователь создает первую запись
- Запись сохраняется в `entries`
- Срабатывает Database Webhook → push-realtime-trigger
- Отправляется push-уведомление "✅ Запись сохранена!"

**Шаг 5**: Пользователь возвращается на главный экран
- Frontend вызывает `GET /home-screen-data`
- motivations находит 1 запись за 48 часов
- Создает 1 карточку из записи
- Добавляет 2 шаблонные карточки
- Возвращает: 1 карточка из записи + 2 шаблонные

**Результат**: Пользователь видит свою запись как карточку с AI инсайтом

**Исходное состояние**:
- Пользователь создал 15 записей за неделю
- Последние 48 часов: 5 записей (E1, E2, E3, E4, E5)
- Просмотрел карточки: E1, E2 (в motivation_cards)

**Шаг 1**: Пользователь открывает главный экран (утро)

- Фильтрует просмотренные: [E1, E2]
- Непросмотренные: [E3, E4, E5]
- Возвращает: 3 карточки из E3, E4, E5

**Результат**: Пользователь видит 3 новые карточки с AI инсайтами

**Шаг 2**: Пользователь свайпает все 3 карточки
- Вызывается `POST /motivations/mark-read` для E3, E4, E5
- Создаются записи в motivation_cards
- Все карточки исчезают

**Шаг 3**: Пользователь pull-to-refresh
- motivations находит 5 записей за 48 часов
- Фильтрует просмотренные: [E1, E2, E3, E4, E5]
- Непросмотренные: []
- Добавляет 3 шаблонные карточки
- Возвращает: 3 шаблонные карточки

**Результат**: Пользователь видит мотивационные сообщения (все записи просмотрены)

**Шаг 4**: Пользователь создает новую запись E6
- Запись сохраняется в `entries`
- Срабатывает Database Webhook
- Отправляется push-уведомление

**Шаг 5**: Пользователь возвращается на главный экран
- motivations находит 6 записей за 48 часов (E1-E6)
- Фильтрует просмотренные: [E1, E2, E3, E4, E5]
- Непросмотренные: [E6]
- Создает 1 карточку из E6
- Добавляет 2 шаблонные карточки
- Возвращает: 1 карточка из E6 + 2 шаблонные

**Результат**: Пользователь видит новую карточку с только что созданной записью

### Сценарий 3: Пользователь с перерывом (возвращается через 3 дня)

## ⚠️ Критические проблемы и решения

### Проблема 1: Архитектурная ошибка (ИСПРАВЛЕНО 2025-11-15)

**Описание**: home-screen-data Edge Function запрашивал карточки из таблицы `motivation_cards` с фильтром `is_read = false`

**Root Cause**:
- Неправильное понимание назначения таблицы `motivation_cards`
- Таблица - это ЛОГ просмотренных карточек, а НЕ источник карточек
- В таблице ТОЛЬКО просмотренные карточки (is_read = true)
- Запрос с фильтром `is_read = false` возвращал пустой массив

**Последствия**:
- Пользователи видели пустой экран AI Insights
- Карточки не показывались после деплоя
- Затронуты ВСЕ пользователи

**Решение**:
```typescript
// ❌ БЫЛО (неправильно):
const motivationCards = await supabase
  .from('motivation_cards')
  .select('*')
  .eq('user_id', userId)
  .eq('is_read', false); // Всегда пустой массив!

// ✅ СТАЛО (правильно):
const motivationsUrl = `${supabaseUrl}/functions/v1/motivations/cards/${userId}`;
const motivationsResponse = await fetch(motivationsUrl, {
  headers: {
    Authorization: `Bearer ${supabaseKey}`,
  },
});
const motivationCards = await motivationsResponse.json();
```

**Статус**: ✅ Исправлено, задеплоено (version 4)

### Проблема 2: 404 ошибки для CSS файлов после деплоя

**Описание**: После нового build пользователи видят 404 ошибки для CSS файлов в консоли браузера

**Root Cause**:
- Vite генерирует CSS файлы с хешами в именах (например, `index-Ds7XLCxp.css`)
- После нового build хеши меняются (например, `index-NEW_HASH.css`)
- Браузер кеширует старый HTML с ссылками на старые CSS файлы
- Service Worker НЕ обновляется автоматически у всех пользователей

**Почему Service Worker не помог**:
1. **Service Worker регистрируется правильно** (`public/service-worker.js`)
2. **Cache версия обновляется** (через `generate-sw-version.js` на основе git hash)
3. **skipWaiting() вызывается** (строка 35 в service-worker.js)
4. **clients.claim() вызывается** (строка 58 в service-worker.js)

**НО**: Проблема в том что:
- Service Worker обновляется ТОЛЬКО при перезагрузке страницы
- Если пользователь НЕ перезагружает страницу → старый SW остается активным
- Старый SW кеширует старые CSS файлы
- Новый HTML ссылается на новые CSS файлы → 404

**Решение**:
1. **Краткосрочное** (для пользователей):
   - Hard Reload (Ctrl+Shift+R или Cmd+Shift+R)
   - Очистить кеш браузера
   - Открыть в режиме инкогнито

2. **Долгосрочное** (для разработчиков):
   - ✅ УЖЕ РЕАЛИЗОВАНО: PWAUpdatePrompt компонент
   - ✅ УЖЕ РЕАЛИЗОВАНО: Автоматическое обновление (autoUpdateEnabled = true)
   - ✅ УЖЕ РЕАЛИЗОВАНО: Проверка версии в main.tsx
   - ⚠️ ПРОБЛЕМА: Пользователи НЕ видят уведомление об обновлении

**Почему пользователи не видят уведомление**:
- PWAUpdatePrompt показывается ТОЛЬКО если `registration.waiting` существует
- Но если пользователь НЕ перезагружает страницу → новый SW НЕ становится waiting
- Новый SW остается в состоянии installing → никогда не переходит в waiting

**Правильное решение** (TODO):
```typescript
// В PWAUpdatePrompt.tsx добавить проверку installing state
if (registration.installing) {
  console.log('[PWA Update] Installing worker found, forcing update...');
  setShowUpdate(true);
  setIsUpdating(true);

  // Ждем когда installing станет installed
  registration.installing.addEventListener('statechange', (e) => {
    const sw = e.target as ServiceWorker;
    if (sw.state === 'installed') {
      sw.postMessage({ type: 'SKIP_WAITING' });
    }
  });
}
```

**Статус**: ⚠️ Частично решено (автообновление работает, но не для всех случаев)
