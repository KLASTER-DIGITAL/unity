# Рекомендации по системе книг UNITY

## Стратегические рекомендации

### 1. "Легализация" текущего кода
Так как код значительно опережает документацию, рекомендуется официально признать текущую ветку разработки "релизной" для фазы 1 и 2.
*   **Действие**: Обновить `BOOKS_SYSTEM_MASTER.md`, отметив все P0 и P1 задачи как выполненные.

### 2. Фокус на качестве Frontend
Backend готов к масштабированию, но Frontend имеет технический долг (дубликаты).
*   **Действие**: Провести "неделю качества" для рефакторинга `features/mobile/reports/`. Удалить все файлы `.native.tsx`, если они дублируют функционал в подпапках. Унифицировать стили.

### 3. Структура книги (Story + Chronicle)

**Суть**: Пользователь хочет видеть и AI-историю, и свои сырые записи.
**Решение**:
- **Часть 1: История**. Красивые главы, выводы, фото.
- **Часть 2: Хроника**. Полный список записей за период (как в Free), чтобы ничего не потерять.
- Добавить опцию `include_raw_entries: boolean` в настройки генерации.

## Технические рекомендации

### 1. Тестирование PDF
Puppeteer — мощный инструмент, но капризный по памяти.
*   **Рекомендация**: Следить за логами `books-render-puppeteer` на предмет ошибок "Out of memory". Если будут падения, рассмотреть вариант использования сервиса (например, Browserless.io) или оптимизации запуска браузера.

### 2. Offline-first подход
Для мобильного приложения критически важно, чтобы скачанная книга была доступна в самолете.
*   **Рекомендация**: Использовать `expo-file-system` (если это Expo) или `rn-fetch-blob` для сохранения PDF в локальную файловую систему устройства, а не просто кэшировать URL.
- **Library Flow**: Сделать "Edit -> Overwrite" основным сценарием. Версионирование спрятать в "Дублировать".
- **Offline Mode**: Критично для чтения PDF в дороге.

### 3. Улучшение промптов (AI Style Guide)
В коде есть хардкод промптов (fallback), если не загружен конфиг из БД.
*   **Рекомендация**: Перенести все промпты в базу данных (`ai_operations`) и создать админку для их редактирования. Это позволит менять стиль книг без пересборки и деплоя Edge Functions.

### 4. Аналитика
*   **Рекомендация**: Добавить событие `book_generated` в аналитику (PostHog/Amplitude) с параметрами `plan_type`, `style`, `pages_count`. Это поможет понять, какие книги реально создают люди.
