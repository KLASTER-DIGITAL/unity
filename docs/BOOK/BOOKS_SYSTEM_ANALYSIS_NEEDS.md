# Анализ системы книг UNITY

## 1. Общее состояние
**Статус**: 🟢 Отличное (Backend опережает документацию)

Проведенный анализ показал, что текущая реализация системы книг (особенно Backend) находится на гораздо более продвинутой стадии, чем описано в `BOOKS_SYSTEM_MASTER.md`. Многие функции, помеченные как "Критические проблемы" или "План на будущее", **уже реализованы**.

---

## 2. Что реализовано ХОРОШО (✅)

### Backend (Supabase Edge Functions)
*   **Разделение Free / Premium**: Реализовано.
    *   Есть отдельная функция `books-generate-free` для бесплатного тарифа (без AI, быстрая генерация).
    *   Функция `books-generate-draft` поддерживает параметр `planType`.
*   **Оптимизация AI**:
    *   Используются `entry_summaries` вместо сырых записей (экономия токенов ~90%).
    *   Реализовано агрессивное кэширование через Content Hash.
*   **Context Engine**:
    *   AI получает контекст из `monthly_snapshots` (эмоции, темы, люди).
    *   Извлекаются персоны (`persons`) для создания персональных глав.
*   **PDF Рендеринг**:
    *   Реализован серверный рендеринг через Puppeteer (`books-render-puppeteer`).
    *   Поддержка шрифтов Noto Sans для корректного отображения всех языков.
    *   Поддержка темной/светлой темы.

### Архитектура
*   Четкое разделение ответственности между функциями.
*   Использование `monthly_snapshots` для быстрой аналитики.
*   Автоматическая привязка фото к главам.

---

## 3. Что реализовано ПЛОХО / Требует внимания (⚠️)

### Frontend (Мобильное приложение)
*   **Дублирование кода**:
    *   Обнаружены дубликаты компонентов визарда:
        *   `features/mobile/reports/components/BookCreationWizard.native.tsx`
        *   `features/mobile/reports/components/book-creation-wizard/BookCreationWizard.tsx`
    *   Это усложняет поддержку и может привести к багам, когда правится один файл, а используется другой.
*   **Сложность навигации**: Логика переходов между шагами визарда смешана с логикой загрузки данных пользователя.

### Документация
*   **Рассинхронизация**: Master-документ утверждает, что критические функции (Free tier, Snapshots, Puppeteer) *отсутствуют*, хотя код для них написан и выглядит рабочим. Это вводит в заблуждение команду разработки.
