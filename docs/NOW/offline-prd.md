# 📴 Offline Mode — PRD (Premium Feature)

**Версия:** 1.0  
**Дата:** 29 октября 2025  
**Статус:** ✅ В Production  
**Автор:** UNITY Product Team

---

## 🎯 Цель функции

Offline Mode обеспечивает пользователю возможность использовать UNITY без интернета, сохраняя записи локально и синхронизируя их автоматически при восстановлении сети.

Эта функция доступна только **Premium-пользователям** 💎.

---

## 💡 Ключевая идея

UNITY должен оставаться полезным в любых условиях — в путешествии, в самолёте, на даче, в метро или просто при плохом интернете.

**Offline Mode превращает UNITY в автономный дневник достижений, который всегда под рукой и работает без задержек.**

---

## ⚙️ Основная логика работы

### 1. Проверка состояния сети

- При запуске приложения система определяет `navigator.onLine` (Web) или `NetInfo` (React Native)
- Если соединение отсутствует → автоматически активируется Offline Mode
- Индикатор в аватаре показывает текущий статус

### 2. Работа офлайн

| Функция | Поведение |
|---------|-----------|
| **Создание текстовой записи** | ✅ Сохраняется локально (IndexedDB / SQLite) |
| **Голосовая заметка** | ✅ Сохраняется локально, транскрибация позже |
| **Фото / медиа** | ✅ Кэшируются локально, загружаются после синхронизации |
| **AI-анализ** | ⏳ Недоступен, placeholder "Инсайт появится после синхронизации" |
| **Просмотр записей** | ✅ Показываются последние закэшированные записи |
| **Статистика** | ✅ Рассчитывается по локальным данным |
| **Настройки** | ✅ Сохраняются локально |

### 3. Синхронизация

При восстановлении интернета приложение автоматически:

1. **Отправляет** все несинхронизированные записи на Supabase
2. **Запускает** AI-анализ записей (summary, insight, sentiment, tags)
3. **Обновляет** локальную базу с актуальными данными
4. **Показывает** экран "✅ Синхронизация завершена"

**Стратегия синхронизации:**
- Background Sync API (если поддерживается)
- Fallback: автоматическая синхронизация при событии `online`
- Периодическая проверка каждые 30 секунд
- Retry logic: до 3 попыток с экспоненциальной задержкой

### 4. Разрешение конфликтов

Если запись изменилась и локально, и на сервере:

| Стратегия | Описание | Когда использовать |
|-----------|----------|-------------------|
| **Server Wins** 🏆 | Сервер всегда прав | По умолчанию, критичные данные |
| **Client Wins** 📱 | Клиент всегда прав | Личные настройки, черновики |
| **Merge** 🔀 | Объединение изменений | Несвязанные поля (теги, категории) |
| **Manual** 👤 | Пользователь выбирает | Важные конфликты |

## 🔐 Техническая реализация

| Компонент | Технология |
|-----------|------------|
| **Локальная БД (Web)** | IndexedDB (база `unity-diary-offline`) |
| **Локальная БД (React Native)** | SQLite через expo-sqlite |
| **Фоновая очередь** | `pending_entries` — хранит несинхронизированные записи |
| **Кэширование статики** | Service Worker с 3 стратегиями (Network-First, Stale-While-Revalidate, Cache-First) |
| **API синхронизации** | Supabase REST API (через `createEntry`) |
| **Background Sync** | Web Push API + Service Worker (Web), Background Tasks (React Native) |
| **Флаг премиум** | `profiles.is_premium = true` в Supabase |

### Хранилища данных

**Web Platform (PWA):**
- IndexedDB: `pending_entries`, `cached_entries`, `sync_queue`
- Cache API: статические файлы, изображения
- Service Worker: обработка offline запросов

**React Native:**
- SQLite: `pending_entries`, `cached_entries`
- AsyncStorage: настройки, флаги
- Expo FileSystem: медиа-файлы

### Стратегии кэширования (Service Worker)

| Тип контента | Стратегия | TTL |
|--------------|-----------|-----|
| HTML-страницы | Network-First | 24 часа |
| API-запросы | Stale-While-Revalidate | 5 минут |
| Статика (CSS/JS) | Cache-First | 24 часа |
| Изображения | Cache-First | 7 дней |

| 🔴 **Офлайн** | Красный | — | Работает Offline Mode |

### 💬 Дополнительные UI элементы

**1. Offline Mode Badge**

При offline режиме показывается серый бейдж в верхней части экрана:

```
┌──────────────────────────┐
│ 📴 Offline Mode (3)      │
└──────────────────────────┘
```

- Показывает количество несинхронизированных записей
- Исчезает при успешной синхронизации

**2. Sync Completion Modal**

После успешной синхронизации:

```
┌─────────────────────────────┐
│     ✅ Синхронизация         │
│       завершена!             │
│                              │
│   Синхронизировано: 5        │
└─────────────────────────────┘
```

- Автозакрытие через 2 секунды
- Показывает статистику синхронизации

**3. Настройки Offline (Settings → Offline режим)**

| Элемент | Описание |
|---------|----------|
| **Toggle "Включить offline режим"** | Premium-only (заблокирован для Free) |
| **Статус сети** | 🟢 Online / 🔴 Offline + время последней синхронизации |
| **Автосинхронизация** | Toggle для автоматической синхронизации |
| **Стратегия конфликтов** | Radio buttons: Server wins / Client wins / Merge / Manual |
| **Pending записи** | Счётчик + кнопка "Синхронизировать сейчас" |
| **Размер кэша** | Slider 10-100 МБ + текущее использование |
| **Очистить данные** | Кнопка с подтверждением |

**4. Conflict Resolution Modal**

При обнаружении конфликта (strategy = "manual"):

- Показывает серверную и клиентскую версию записи
- Timestamp каждой версии
- Кнопки: "Использовать серверную" / "Использовать мою" / "Объединить"

## 📲 Пользовательский сценарий

**Сценарий: Дмитрий в командировке без интернета**

1. Дмитрий включает **Premium** и активирует **Offline Mode** в настройках UNITY
2. Уезжает в командировку в регион с плохой связью
3. Каждый день делает записи достижений — текстом и голосом. UNITY показывает бейдж **"📴 Offline Mode"**
4. AI-инсайты временно недоступны, но записи сохраняются локально
5. Через три дня возвращается в город, интернет восстанавливается
6. UNITY автоматически запускает синхронизацию и AI-анализ всех записей
7. Через 10 секунд появляется экран: **"✅ Синхронизация завершена. AI-инсайты готовы"**
8. Дмитрий видит все свои записи с готовыми инсайтами, тегами и sentiment-анализом

## 📚 Техническая документация

**Для разработчиков доступна детальная техническая документация:**

### Архитектура

- **Offline Manager** (`src/shared/lib/offline/offlineManager.ts`)  
  Singleton для управления статусом сети, синхронизацией и конфликтами

- **Background Sync API** (`src/shared/lib/offline/backgroundSync.ts`)  
  Сохранение записей offline и автосинхронизация

- **IndexedDB / SQLite** (`src/shared/lib/offline/indexedDB.ts`)  
  Локальное хранилище с 3 stores: `pending_entries`, `cached_entries`, `sync_queue`

- **Platform Adapters** (`src/shared/lib/platform/offline/`)  
  Cross-platform API для Web (IndexedDB) и React Native (SQLite)

- **Service Worker** (`public/service-worker.js`)  
  Кэширование статики с 3 стратегиями + Background Sync handler

### UI Компоненты

- `NetworkStatusIndicator` — индикатор в аватаре (🟢🟡🔴)
- `OfflineModeBadge` — бейдж "Offline Mode" с pending count
- `OfflineSyncIndicator` — список pending записей с actions
- `SyncCompletionModal` — экран успешной синхронизации
- `ConflictResolutionModal` — UI для ручного разрешения конфликтов
- `OfflineSection` — секция настроек Offline Mode
- `OfflineSettingsModal` — детальные настройки offline

### React Hook

```typescript
import { useOfflineMode } from '@/shared/lib/offline';

const { 
  isOnline, 
  pendingCount, 
  syncInProgress,
  sync,
  clearOfflineData 
} = useOfflineMode();
```
