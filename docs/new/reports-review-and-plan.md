## 1. Что уже хорошо в текущей системе отчетов

По `REPORTS_SYSTEM.md` сейчас реализовано:

1. **Чёткая структура типов отчётов**

   - `MonthlyReport` со всеми ключевыми полями:
     - период, общее количество записей;
     - streak (серия дней);
     - распределение настроений (`moodDistribution`);
     - топ категорий (`topCategories`);
     - список ключевых достижений (`keyAchievements`);
     - AI-комментарии (`aiComments`).
   - `PDFReportData` для генерации PDF:
     - данные пользователя, язык, период;
     - статистика, графики, список записей;
     - AI Summary по записям.

2. **Разделение Free / Premium-функционала**

   - Free:
     - просмотр базового месячного отчёта;
     - карточки «Всего записей», «Серия», «Настроение»;
     - простые графики (mood, категории).
   - Premium:
     - AI-инсайты и комментарии;
     - экспорт PDF-отчёта;
     - создание книга из записей.

3. **Сценарии использования**

   Описаны сценарии:

   - Сценарий 1: просмотр месячного отчёта (Free);
   - Сценарий 2: просмотр отчёта с AI-инсайтами (Premium);
   - Сценарий 3: экспорт PDF-отчёта (Premium);
   - Сценарий 4: создание книги из записей (Premium).

   Для каждого есть шаги, что упрощает реализацию и тестирование.

4. **Компоненты UI**

   - `ReportsScreen` с табами Overview / Details / Books;
   - карточки статистики (`StatsCard`);
   - графики (PieChart, BarChart) с ленивой загрузкой;
   - базовая интеграция с PWA и React Native.

5. **Единый `statsCalculator`**

   - Логика расчёта статистики вынесена в отдельные функции:
     - `calculateUserStats`;
     - `calculateMoodDistribution`;
     - `calculateTopCategories`;
     - `calculateStatsForPdf`.
   - Это уже используется и в Achievements, и в Reports.

В целом: **базовый слой отчетности реализован**, есть понятные типы данных, UI и разделение по тарифам.

## 2. Ограничения и проблемы текущей реализации

Несмотря на хороший фундамент, в `REPORTS_SYSTEM.md` и сопутствующих документах видны ограничения:

1. **Расчёт статистики только на клиенте**

   - Статистика считается в `statsCalculator` на фронтенде из «последних N записей» (часто 100).
   - Проблемы:
     - отчёт за «месяц» может быть неточным, если записей больше 100;
     - тяжело масштабировать на большие истории дневника;
     - логика дублируется между PWA и React Native;
     - нет серверной агрегации для лёгких запросов (API виджетов, OS-виджеты, отчёты по e-mail и т.п.).

2. **Слабая связь с Achievements**

   - Поле `keyAchievements` заполняется на основе записей, а не на основе фактических достижений (`user_achievements`);
   - Нельзя показать:
     - «новые достижения за период»;
     - «легендарные достижения за всё время»;
     - прогресс к важным целям.

3. **Ограниченность по периодам**

   - Реально описан только «месячный отчет»;
   - Нет чётких структур для:
     - недельного отчёта (который важен для привычки);
     - квартального/годового обзора;
     - отчёта по конкретному фокусу (семья, здоровье и т.п.).

4. **AI-часть не вынесена в AI Control Center**

   - Промпты для AI-инсайтов и PDF-отчётов описаны текстом, но:
     - не привязаны к операциям `weekly_report` / `monthly_report` / `pdf_book_outline`;
     - не управляются из админки;
     - тяжелее менять тон и структуру без редеплоя.

5. **PDF-пайплайн частично дублирует `ai-pdf-books.md`**

   - В `REPORTS_SYSTEM.md` есть `PDFReportData`, а в `ai-pdf-books.md` — свои структуры `BookDraft`, `BookChapter`, `BookMeta`;
   - Нет единой модели:
     - «месячный отчёт» как глава книги;
     - «книга года» как сборка из месяцев.

6. **Не учтён offline-mode в UI отчётов**

   - В `offline-prd.md` описано, что:
     - статистика может показываться из локального кэша;
     - PDF-генерация доступна только онлайн.
   - В текущем описании Reports нет явного UX для состояний:
     - «нет сети, показываем последнюю синхронизацию»;
     - «отчёт за месяц ещё не посчитан, идёт расчёт».

## 3. Целевая модель раздела «Отчёты»

### 3.1. Два уровня отчётности

1. **In-app отчёт (Dashboard)**

   - Быстрая картинка за выбранный период:
     - количество записей и достижений;
     - динамика настроения;
     - фокусы (категории);
     - прогресс (серия, уровень).
   - Представлен в виде:
     - карточек (как на референсах дизайна);
     - нескольких графиков.

2. **Narrative-отчёт (AI-текст + PDF)**

   - Текстовый обзор с инсайтами:
     - «что было важного за неделю/месяц»;
     - «как менялось состояние»;
     - «какие достижения особенно ценны».
   - Может быть:
     - просто текст на вкладке «Отчёт»;
     - частью PDF-книги (месяц = глава).

### 3.2. Основные типы отчётов

Рекомендуемый минимум:

- **Недельный отчёт (WeeklyReport)** — основной для привычки;
- **Месячный отчёт (MonthlyReport)** — более глубокий срез;
- **Годовой обзор / книга** — сборка из месяцев.

С точки зрения типов:

```ts
type WeeklyReport = {
  period: string;              // "Неделя 45, 2025"
  startDate: string;
  endDate: string;
  totalEntries: number;
  totalAchievements: number;
  currentProgressDays: number; // серия по дням
  moodDistribution: MoodStat[];
  topCategories: CategoryStat[];
  newAchievements: AchievementSummary[]; // за неделю
  aiSummary?: string;          // Premium
  aiInsights?: string[];       // Premium
};

type MonthlyReport = {
  // как в REPORTS_SYSTEM.md, но + newAchievements, totalAchievements и link to PDF
};
```

## 4. Данные и архитектура для отчётов

### 4.1. Server-side статистика

Чтобы уйти от чисто клиентских расчётов:

1. Ввести материализованные таблицы / представления в Supabase:

```sql
CREATE TABLE user_stats_daily (
  user_id UUID NOT NULL,
  date DATE NOT NULL,
  entries_count INT NOT NULL,
  achievements_count INT NOT NULL,
  positive_count INT NOT NULL,
  neutral_count INT NOT NULL,
  negative_count INT NOT NULL,
  top_category TEXT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (user_id, date)
);

CREATE TABLE user_stats_monthly (
  user_id UUID NOT NULL,
  year INT NOT NULL,
  month INT NOT NULL,
  entries_count INT NOT NULL,
  achievements_count INT NOT NULL,
  avg_mood NUMERIC NULL,
  top_categories JSONB NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  PRIMARY KEY (user_id, year, month)
);
```

2. Заполнение:

   - либо через cron-задачу (ежедневно/ежемесячно);
   - либо через edge-функцию, которая вызывается при создании/изменении записей (с аккуратным кешированием).

3. Frontend тогда:

   - не тянет все записи для расчёта;
   - запрашивает `user_stats_daily`/`monthly` по периоду;
   - использует их для отчётов, виджетов и Achievements.

### 4.2. Кэш AI-отчётов

Добавить таблицу `user_reports`:

```sql
CREATE TABLE user_reports (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL,
  period_type TEXT NOT NULL,        -- 'weekly' | 'monthly'
  period_key TEXT NOT NULL,         -- '2025-11', '2025-W45'
  language TEXT NOT NULL,
  is_premium BOOLEAN NOT NULL,
  stats JSONB NOT NULL,             -- snapshot статистики
  ai_summary TEXT NULL,
  ai_insights JSONB NULL,
  pdf_url TEXT NULL,                -- если PDF уже сгенерирован
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE (user_id, period_type, period_key)
);
```

- AI-операции `weekly_report`/`monthly_report` берут:
  - статистику из `user_stats_*` + свежие достижения;
  - генерируют текст;
  - сохраняют в `user_reports`.
- При открытии вкладки «Отчёты»:
  - если запись уже есть → показываем моментально;
  - если нет и пользователь Premium → запускаем генерацию (с состоянием «Готовим отчёт…»).

## 5. Связка «Отчёты ↔ Достижения ↔ Карточки ↔ Push»

### 5.1. Достижения в отчётах

- В weekly/monthly отчёт включаем:

  - `newAchievements`: достижения, которые появились за период (из `user_achievements`);
  - `totalAchievements`: общее число, `legendaryAchievements`: редкие.

- AI-промпт для `weekly_report`/`monthly_report` получает это и описывает:
  - «На этой неделе ты получил достижения …»;
  - «За месяц ты сделал N важных шагов в сфере здоровья/семьи».

### 5.2. Карточки и отчёты

- AI-карточки типа `progress` и `reflect` могут использовать данные последнего отчёта:
  - кратко подсвечивать выводы отчёта;
  - приглашать открыть полный отчёт.

- Пример сценария:
  - после генерации месячного отчёта → создать 1–2 карточки с ключевыми инсайтами.

### 5.3. Push-уведомления и отчёты

Используем `push_text`:

- `push_type = "weekly_report_ready"` — «Готов отчёт за неделю, хочешь посмотреть?».
- `push_type = "monthly_report_ready"` — «Твой месяц собран в одну историю».
- (Опционально) `push_type = "report_summary"` — краткий инсайт из последнего отчёта.

Супер-админ может включать/выключать эти типы push.

## 6. UX: экран «Отчёты» и виджеты

### 6.1. Обновлённый ReportsScreen

Вдохновляясь референсами дизайна (календарь + цветные карточки):

**Структура вкладки Overview:**

- Header:
  - аватар, «Привет, Имя», выбранный период (Неделя/Месяц);
- Horizontal date picker (как во втором референсе):
  - недели/дни для Weekly;
  - месяцы для Monthly;
- Статистические карточки:
  - «Записи за период»;
  - «Прогресс по дням» (streak);
  - «Настроение периода»;
  - «Фокусные категории».
- Кнопки:
  - [Сгенерировать отчёт] (если ещё нет);
  - [Скачать PDF] (для Premium при наличии PDF).

**Вкладка Insights (Premium):**

- Текстовый AI-отчёт:
  - делится на секции: «Главное», «Настроение», «Достижения», «Намерения»;
- Кнопка «Создать карточку из отчёта» (генерирует 1–2 карточки progress/reflect).

**Вкладка Books (Premium):**

- Список прошлых PDF-книг (месяцы/годы);
- Кнопка «Создать книгу года».

### 6.2. Главная страница и виджеты

На главном экране UNITY (рабочий стол) можно использовать отчётные данные в виджетах:

- «Фокус недели» (короткий инсайт из WeeklyReport);
- «Прогресс месяца» (кольцевой индикатор выполненных дней/записей);
- «Настроение недели» (эмоджи + короткий текст).

Эти виджеты можно включать/выключать в настройках пользователя.

## 7. Роль супер-админа в системе отчётов

Через AI Control Center и отдельный раздел «Reports»:

1. **AI-промпты для отчётов**

   - Управление операциями:
     - `weekly_report`;
     - `monthly_report`;
     - `pdf_book_outline` (если используется).
   - Редактирование:
     - System prompt (тон, стиль);
     - User template (какие данные передаются, структура ответа).
   - Тестирование на примерах статистики.

2. **Настройки периодов и уровней доступа**

   - Включение/выключение Weekly/Monthly report;
   - Решение, что доступно в Free:
     - только базовые карточки и графики;
     - или лёгкий текстовый summary без AI;
   - Настройки Premium:
     - наличие AI-инсайтов;
     - разрешение на PDF/книги.

3. **Мониторинг использования**

   - В будущем: дашборд для супер-админа:
     - сколько пользователей открывают отчёты;
     - сколько отчётов сгенерировано в месяц;
     - средняя стоимость AI по отчетам.

## 8. Roadmap по разделу «Отчёты»

### Этап 1 — Архитектура данных и server-side статистика

- Создать таблицы `user_stats_daily`, `user_stats_monthly`, `user_reports`.  
- Написать cron/edge-функции для расчёта статистики по пользователям.

### Этап 3 — PDF и книги

- Объединить `PDFReportData` и структуры из `ai-pdf-books.md`.  
- Реализовать:
  - экспорт месячного отчёта в PDF;
  - сборку годовой книги из 12 MonthlyReport + Achievements.

- Обновить `ReportsScreen` в стиле современных референсов.

### Этап 5 — Админка и аналитика

- В супер-админке:
  - выделить секцию «Reports & Books»;
