# UNITY — Ревью и план развития раздела «Достижения»

Файл: `achievements-review-and-plan.md`  
Версия: 1.0  
Дата: 2025-11-15  

Этот документ дополняет:

- `ACHIEVEMENTS_SYSTEM.md` — текущая реализация системы достижений UNITY-v2;
- `REPORTS_SYSTEM.md` — текущая реализация системы отчетов;
- `cards-and-push-tech.md` / `cards-and-push-scenarios.md` — карточки и push;
- `ai-prompts-cards.md` — промпты для карточек и push;
- `ai-superadmin-settings.md` — AI-настройки в кабинете супер-админа;
- `achievements-and-reports.md` — общая концепция «Достижения + Отчёты».

Цель — дать **объединённый взгляд на раздел «Достижения»**, оценить, что уже хорошо, что нужно улучшить, и предложить план развития с учётом:

- онбординга и ежедневного сценария пользования;
- AI-карточек и push-уведомлений;
- будущих виджетов на главном экране и OS-виджетов;
- кабинета супер-админа и AI Control Center.

---

## 1. Что уже хорошо в текущей системе достижений

По `ACHIEVEMENTS_SYSTEM.md` текущая система уже имеет сильный фундамент:

1. **Чёткая архитектура компонентов**  
   - Отдельные экраны для PWA и React Native (`AchievementsScreen`, `AchievementCard`, `MilestoneCard` и т.п.).  
   - Общий `statsCalculator.ts` с расчётом streak, уровня, настроений, категорий и инсайтов.

2. **Продуманные метрики геймификации**
   - Серия (streak) — текущая и максимальная серия дней.  
   - Уровень (level) и XP (10 XP за запись, уровень каждые 100 XP).  
   - Базовый набор достижений и вех (первые шаги, неделя подряд, месяц подряд, 10/50 записей и т.д.).

3. **Сценарии использования**
   - Описаны сценарии для нового пользователя, активного пользователя, прогресса к достижению и легендарных достижений.  
   - Есть понимание редкости (rarity) достижений и визуальной дифференциации.

4. **UI-компоненты и визуальный язык**
   - Карточки с иконками, градиентами по редкости, прогресс-барами.  
   - Уже выделены будущие улучшения: анимации, конфетти, skeleton-состояния.

5. **Единый statsCalculator для Achievements + Reports**
   - Одна и та же логика используется и в отчётах (`calculateUserStats`, `calculateMoodDistribution`, `calculateTopCategories`), что упрощает поддержку.

Это хороший базис: **все основные числа для геймификации уже считаются, UI есть, сценарии описаны.**

## 2. Основные ограничения и пробелы текущей реализации

При этом в документах зафиксированы и текущие проблемы:

1. **Нет персистентности достижений**  
   - Сейчас достижения **каждый раз пересчитываются на клиенте** при загрузке экрана.  
   - Нет таблицы `user_achievements` / `user_milestones` →  
     - невозможно хранить историю («когда именно получил достижение»);  
     - нельзя отправлять push «Ты только что получил достижение»;  
     - тяжело строить отчёты и AI-карточки вокруг «новых достижений».

2. **Нет интеграции с push и AI-карточками**
   - В `ACHIEVEMENTS_SYSTEM.md` push и AI упомянуты в «Будущих улучшениях», но не реализованы.  
   - Система достижений живёт отдельно от системы мотивационных карточек и push-уведомлений.

3. **Ограниченный каталог достижений**
   - Список достижений и вех небольшой, в основном про «количество записей» и «серии».  
   - Почти нет достижений по **контекстам** (семья, здоровье, работа, духовность и т.п.) и по **эмоциям**.  
   - Нет «мягких» достижений, связанных с осознанностью: «честно написал про сложный день», «вернулся после перерыва».

4. **Нет персонализации и AI-связки**
   - Достижения не используют AI-анализ записей (summary, insight, category, mood) для определения «важных» побед.  
   - Нет связки с `is_achievement` на уровне записи (хотя поле есть в таблице `entries`).

5. **Нет связи с кабинетом супер-админа**
   - Пороговые значения, список достижений, тексты/иконки **зашиты в код**.  
   - Супер-админ не может:
     - включать/выключать конкретные достижения;
     - настраивать пороги (7 дней подряд, 3 дня, 14 и т.п.);
     - менять названия/описания под аудиторию.

6. **Стрик в UI всё ещё «Streak»**
   - В проектной логике мы хотим на пользовательском уровне использовать термин «Прогресс», а не «Streak».  
   - Сейчас streak используется как термин геймификации; нужен аккуратный rebranding в пользовательском интерфейсе (оставив streak как внутреннее поле).

7. **Нет привязки к будущей системе виджетов**
   - Achievements уже считают нужные числа, но нет задуманных **мини-виджетов**:
     - «Прогресс за сегодня»;
     - «Серия дней»;
     - «Ты на 80% к новому достижению».

## 3. Целевая модель раздела «Достижения»

### 3.1. Общая идея

Раздел «Достижения» должен стать:

- **центральным слоем геймификации** в UNITY;
- связкой между:
  - ежедневными записями,
  - мотивационными карточками,
  - push-уведомлениями,
  - отчетами и PDF-книгами,
  - виджетами на главном экране и OS-виджетами,
  - настройками супер-админа.

### 3.2. Уровни данных

1. **Запись (entry)**  
   - `is_achievement` (bool) — явное/AI-обнаруженное достижение.  
   - AI-мета: summary, insight, category, mood.

2. **Технические метрики (stats)**  
   - totalEntries, currentStreak, longestStreak, level, moodDistribution, topCategories и т.д. (уже есть).

3. **Достижения и вехи (achievement/milestone instances)**  
   - факты: «пользователь получил достижение X в дату Y»;  
   - прогресс: «пользователь продвинулся с 40% до 70% по достижению Z».

4. **Виджеты и отчёты**  
   - используют те же метрики & достижения для визуализации.

## 4. Что нужно доработать в Achievements (по пунктам)

### 4.1. Персистентность достижений

**Задача:**  
Ввести таблицы в Supabase:

```sql
CREATE TABLE achievements_catalog (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  description TEXT NOT NULL,
  icon TEXT NOT NULL,
  rarity TEXT NOT NULL,
  condition JSONB NOT NULL,
  is_enabled BOOLEAN NOT NULL DEFAULT TRUE,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

CREATE TABLE user_achievements (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id UUID NOT NULL,
  achievement_id TEXT NOT NULL REFERENCES achievements_catalog(id),
  earned_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  progress INT NOT NULL DEFAULT 100,
  UNIQUE (user_id, achievement_id)
);
```

**Логика:**

- `calculateAchievements()` больше не только строит список «виртуальных» достижений, а:
  - считает прогресс по каталогу;
  - создаёт/обновляет записи `user_achievements` при выполнении условий;
  - возвращает UI-модель с полями `earned`, `progress`, `earnedDate` уже из БД.

### 4.2. Формализованные условия достижений

Добавить JSON-схему в `condition`:

```json
{ "type": "entries_count", "operator": ">=", "value": 10 }
```

```json
{ "type": "streak_days", "operator": ">=", "value": 7 }
```

```json
{ "type": "category_count", "category": "Спорт", "operator": ">=", "value": 10 }
```

На первом этапе обработка условий остаётся в коде, но сама конфигурация хранится в БД.

### 4.3. Интеграция с AI и `is_achievement`

1. AI-анализ записи (`entry_analysis`) может выставлять `is_achievement = true`, если запись явно о победе/результате.  
2. Пользователь может руками включать/выключать этот флаг.  
3. Добавить достижения на основе `is_achievement`, `sentiment`, `category` (семья, здоровье, честность в сложные дни и т.п.).

### 4.4. Связка с push-уведомлениями

1. **Тип push: `achievement_unlocked`** — триггер при новой записи в `user_achievements`.  
2. **Тип push: `achievement_near`** — триггер при достижении порога прогресса (70–90%).

Тексты генерируются через `push_text` с соответствующим `push_type`.

### 4.5. Связка с отчётами

1. В недельных/месячных отчётах отображать:
   - новые достижения за период;
   - общее количество и легендарные достижения.
2. В AI-операции `weekly_report` и `monthly_report` передавать массив `new_achievements` и статистику по достижениям.

## 5. Онбординг → ежедневный сценарий → Достижения → Отчёты

1. Онбординг: выбор фокусов (семья, здоровье, работа, духовность) и показ первых целей-достижений.  
2. Ежедневный сценарий: записи + отметка достижений, AI-карточки Celebrate/Progress.  
3. Раздел «Достижения»: наглядный прогресс, серия (Прогресс), вехи, новые бейджи.  
4. Раздел «Отчёты»: недельные/месячные обзоры, использующие `user_achievements`.

## 6. Виджеты

### 6.1. На главном экране UNITY

Рекомендуемые виджеты:

- **Daily Challenge / Челлендж дня** — крупный баннер с задачей дня.
- **Progress Ring / Прогресс дня** — кольцевой индикатор выполненных действий.
- **Серия дней** — горизонтальная шкала дней с подсветкой.
- **Ближайшие вехи** — карточки «осталось N до цели».
- **Новые достижения** — слайдер с недавно полученными бейджами.

### 6.2. OS-виджеты (Android / iOS)

- Быстрая запись (кнопка «+ Запись»).
- Сегодняшний прогресс (уровень, серия, краткий AI-текст).
- Фокус недели (краткое напоминание о цели).

---

## 7. Роль супер-админа

- Управление каталогом достижений (создание/редактирование/выключение).
- Настройка условий и редкости.
- Настройка push-сценариев, связанных с достижениями.
- Настройка AI-карточек, использующих достижения (типы карточек, текстовые шаблоны).

---

## 8. Roadmap

1. **Этап 1 — БД и персистентность**: таблицы `achievements_catalog`, `user_achievements`, обновление `calculateAchievements()`.
2. **Этап 2 — AI + push**: связка с `is_achievement`, добавление push-сценариев, интеграция с AI-карточками.
3. **Этап 3 — UI/виджеты**: обновление экрана «Достижения», внедрение виджетов на главной.
4. **Этап 4 — Админка + отчёты**: управление каталогом в супер-админе, полная связка с weekly/monthly отчётами.
